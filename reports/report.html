1. Introduction

Telecom companies lose significant revenue when customers discontinue their subscriptions — a phenomenon known as churn. Early identification of at-risk customers allows retention teams to intervene with targeted offers before the customer leaves.

This project builds a production-ready ML service that predicts individual customer churn probability. The primary learning objective is not to achieve the highest possible accuracy, but to practice the full lifecycle of a production ML system: data preparation, experiment tracking, API serving, containerization, cloud deployment, and operational monitoring.

Business Value

A retention team can use the /predict API to score any customer in real time. Customers with churn_probability > 0.5 are flagged for intervention. The model returns a probability score (0–1) so the team can prioritize the highest-risk cases first.

4.3 Class Imbalance Handling

Two techniques were evaluated:

  • class_weight='balanced' — increases the loss penalty for minority-class errors during training. Used in all sklearn models.
  • SMOTE (Synthetic Minority Over-sampling Technique) — generates synthetic minority-class samples by interpolating between real churner examples. Applied to X_train_proc after preprocessing to prevent any leakage through the imputer or scaler. Training set grew from 4,929 to ~7,200 balanced samples.

Random Forest with class_weight='balanced' slightly outperformed RF+SMOTE (0.8344 vs 0.8333 ROC-AUC), so it was selected as the final model automatically by the pipeline.

10. Conclusion

This project delivered a complete, production-ready customer churn prediction service covering every stage of the MLOps lifecycle:

  • Data: 7-check validation pipeline; clean preprocessing with no leakage
  • Modeling: 6 models trained and compared; Random Forest selected with test ROC-AUC 0.8434
  • Tracking: All experiments reproducible via MLflow; artifacts versioned
  • API: FastAPI service with Pydantic v2 validation, Swagger docs, Prometheus metrics
  • Deployment: Live on Render.com with HTTPS; Kubernetes config included
  • Monitoring: 9-panel Grafana dashboard scraping the live Render endpoint in real time

The system prioritizes reliability and reproducibility over raw accuracy, consistent with the project objectives. Any team member can reproduce the full pipeline by running the notebook and executing docker-compose up -d.
